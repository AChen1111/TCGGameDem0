# TCG Spine 图集排查与修复

工程根目录是本技能目录的 `../../..`；现有脚本必须从工程根目录运行。先读 [图集修复文档](../../../.doc/project/spine-atlas-repair.md)，并检查实际脚本及目标资源；历史扫描数量不是当前检查结果。

## 检查模式

1. 确定目标角色、Unity 资产目录、源资源目录，以及 `.atlas` / `.atlas.txt`、PNG、材质与 SkeletonDataAsset 的对应关系。检查版本、纹理导入和资源引用，避免把所有透明问题都当成坐标错位。
2. 读取 [scan_atlas.py](../../../.tools/scan_atlas.py) 的 `ROOT` 和输出路径。它是批量扫描器，会写扫描报告，且在模块顶层执行；不要为复用解析函数而直接 import 它，也不要捏造不存在的 `--root` 或单包参数。
3. 批量体检请求可在确认源目录存在后运行 `python -X utf8 .tools/scan_atlas.py`。单角色请求只检查目标；如需复用扫描逻辑，做目标明确的临时副本或独立检查，不擅自重写全局 ROOT 并扫整库。
4. 先检查 Python 及实际 import 依赖，缺少依赖时说明缺项，再按任务需要补齐；不要因“检查”请求直接运行修复脚本。
5. 区分 `ok`、`RESCALED`、`BROKEN`。仅整体缩放且归一化 UV 仍正确的页无需修复；低 alpha 覆盖率是疑点，需要结合实际附件和渲染确认。

## 修复模式

- 明确要求修复时，保存目标文件修改前的备份或可恢复差异，保留 `.meta`、GUID、区域名和附件关系。`Recovery` 被 Git 忽略，不能只依赖 Git 恢复源文件。
- [fix_atlas_p14676.py](../../../.tools/fix_atlas_p14676.py) 只适用于 P14676 第一页的特定重排：原声明尺寸与实际美术存在特定比例，并有 Head/Mask、眼睛等消歧逻辑。脚本内硬编码目标目录与尺寸表，执行会写 Assets 和 Recovery 两处；它不是通用 atlas 修复器，也没有 dry-run 开关。
- 目标不是该资源，或输入已不是脚本预期状态时，先建立新的目标限定修复方案。不要把“尺寸除以二”、固定页边界或旋转方向直接推广到其他图集。
- 先计算并检查区域映射：唯一性、页范围、旋转、偏移、透明覆盖率、未修改页面。匹配不唯一或覆盖率异常时停止写入，保留候选与诊断信息。
- 只有本次范围同时包含导入资产与原始资源时才同步修复两处；否则调整执行方案限定目标，避免运行会修改额外文件的脚本。已有明确修复授权不重复询问。

## 验收

1. 对比修复前后区域表，确认只改变需要修复的坐标等字段，原有区域与页引用保持完整；重新检查边界和像素覆盖。
2. 通过当前 Unity Editor 重新导入受影响资源，检查 Console 和 SkeletonDataAsset 关联，不重建无关素材或删除 `.meta`。
3. 在原问题动作及必要的其他动作中检查附件、遮罩、朝向与接缝，保存前后截图。静态覆盖率达标不能替代动画渲染验证。
4. 交付目标路径、原因、修改范围、备份位置及验证结果。编辑器不可用或缺原始图片时说明未验证部分；不要把候选坐标当成已完成修复。
