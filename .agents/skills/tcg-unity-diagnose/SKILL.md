# TCG Unity 故障定位

工程根目录是本技能目录的 `../../..`。按用户请求区分“查看/诊断”和“修复”；后者在已有授权内修复，无需重新确认常规修改。

## 取得当前证据

1. 记录症状、触发动作、Editor/Player、场景、平台、相关工作区改动。读取 [项目版本](../../../ProjectSettings/ProjectVersion.txt) 和 [包依赖](../../../Packages/manifest.json)，不要假定日志来自当前版本。
2. 使用 [Pipeline 连接说明](../../../.doc/unity-pipeline/connectivity.md) 定位当前工程描述文件，核对实例与连接状态。不要硬编码端口，不输出描述文件里的认证令牌；查当前命令目录后按 [日志与编辑器状态文档](../../../.doc/unity-pipeline/commands/editor-lifecycle-and-observability.md) 读取必要范围。
3. 桥接不可用时仍可检查代码、已有日志与编译输出。Windows Editor 日志一般位于 `$env:LOCALAPPDATA/Unity/Editor/Editor.log`；共享日志可能来自其他工程，先核对会话和工程路径，再取尾部相关错误。
4. 保留首次有效错误、完整异常链及项目内首个堆栈位置。按时间和编译批次区分历史错误、新增错误与连锁报错；不清空控制台来制造“无错误”。

## 缩小原因

- 从首个错误定位最小代码或资产范围，先检查程序集引用、字段绑定、路径/GUID、配置就绪和调用顺序。
- [架构文档](../../../.doc/project/architecture.md) 用于定位职责；[故障记录](../../../.doc/project/troubleshooting.md) 只提供候选原因，需要当前证据确认。
- 热更或内容问题沿 `LoadDll → CodeUpdate → 热更入口 → Addressables → 配置` 检查；参考当前源码，不使用已删除的开关和旧发布入口。
- UI 问题区分 Prefab 引用、UISettings 注册、窗口生命周期和运行时会话状态；Spine 缺件先区分图集坐标、材质、贴图与骨骼数据。
- 为每个主要判断写明支持证据及下一项最小验证。不要用删除 Library、重装包、全量重新导入或重启编辑器作为默认诊断步骤。

## 修复

只诊断时停在结论和证据，不借“复现”自动启动游戏。读操作不应调用 `recompile`、菜单、构建或会改变状态的脚本。

修复请求下，先保留受影响文件的已有差异，再做与证据一致的最小修改。

同一工程一次只追踪一个构建任务。编译重载、断连或超时后先查任务状态，不重复提交。开发工作台及其 Play Mode 接管钩子已删除；进入 Play Mode 前仍检查现有启动脚本的副作用，明确可能发生的服务或内容写入是否属于本次请求。

## 输出

用简洁说明交付：症状及发生范围、已确认根因或仍待确认的假设、源码/日志证据、采取的修复。不能复现或无法访问编辑器时明确限制；没有新日志不能证明故障消失。
