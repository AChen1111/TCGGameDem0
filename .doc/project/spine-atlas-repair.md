# Spine 图集坐标排查与修复

`Recovery/SpineAnimations_Complete552` 里的部分 Spine 资源包，`.atlas` 声明的区域坐标和实际 `.png` 对不上：贴图里明明有这块美术，导入 Unity 后对应部件却渲染成全透明（表现为「脸不见了」「手臂缺一块」）。

本文档说明两个配套脚本的用法：

| 脚本 | 作用 |
| --- | --- |
| `.tools/scan_atlas.py` | 批量体检，找出哪些资源包的图集坐标有问题 |
| `.tools/fix_atlas_p14676.py` | 单包修复，按贴图实际像素重建区域坐标并写回 atlas |

## 运行环境

在**工程根目录**下运行，脚本里的路径都是相对根目录的。依赖 `numpy`、`Pillow`、`scipy`，当前环境已安装（2.4.4 / 12.3.0 / 1.17.1）。

```powershell
python .tools/scan_atlas.py
```

## 一、批量体检

`scan_atlas.py` 遍历 `ROOT`（默认 `Recovery/SpineAnimations_Complete552`）下每个子目录，按 `Atlas.cs` 的规则解析 atlas，再把每个区域矩形套到对应 png 的 alpha 通道上，统计非透明像素占比。占比低于 2% 判定为「落在空白像素」。

页尺寸被整体缩放的图仍能正确渲染（Spine 用**声明的**页尺寸归一化 UV），所以脚本会同时试「原样坐标」和「按实际/声明比例换算后的坐标」，取覆盖率更好的一种，避免把整体缩放误报成损坏。

结果写到 `.tools/atlas_scan.txt`，三种状态：

| 状态 | 含义 | 处理 |
| --- | --- | --- |
| `ok` | 坐标与像素一致 | 无需处理 |
| `RESCALED` | 仅页尺寸整体缩放，区域仍能命中像素 | 可正常渲染，只是分辨率变低，不用修 |
| `BROKEN` | 有区域落在空白像素 | 渲染缺件，需要修复 |

最近一次扫描：552 个目录中 234 个 `BROKEN`、60 个 `RESCALED`。报告开头是汇总，`=== 渲染会缺件 ===` 段落逐条列出目录名、区域总数、空白区域数，以及最多 8 个具体区域名。

换一批资源扫描时改脚本顶部的 `ROOT` 即可。

## 二、单包修复

`fix_atlas_p14676.py` 以 `I：P百变莱娜_P14676JS` 为例，修的是「贴图被重新打包过、每块美术恰好是 atlas 声明尺寸的一半」这一类损坏。它的思路是**不信坐标，只信声明的尺寸和贴图像素**：

1. 用 `scipy.ndimage` 对 alpha 做膨胀后连通域分析，量出贴图上每块美术的紧致包围盒；
2. 把每个区域的声明尺寸减半，与包围盒逐一匹配（尺寸差在容差内即为候选），顺带由长宽比判断是否 `rotate:90`；
3. 用「声明尺寸（减半）居中对齐到实测美术范围」算出新的 `bounds`；
4. 校验每个新矩形的 alpha 覆盖率，全部达标才写回 `Assets/.../P14676.atlas.txt` 和 `Recovery/.../P14676.atlas`。

### 两处歧义的消解

- **Head 与 Mask 尺寸相同**：`Mask` 在第二页也有一份且渲染正常，脚本把第一页的两个候选块各自旋转、缩放到第二页 `Mask` 的尺寸后做灰度相似度打分，得分高的是 `Mask`，另一个是 `Head`。
- **Eye1 与 Eye2 在骨架里位置、旋转、尺寸完全相同**（同一只眼睛的两个约 94% 相似的变体），无从区分，按光栅顺序（先上后左）分配。

### 旋转约定

以第二页校准：它的 `Mask` 声明 `rotate:90` 且当前渲染正确，把其打包像素做 `np.rot90(k=3)` 才得到正立美术。因此第一页重打包中所有旋转块同样用 `rotate:90`。

### 安全阀

脚本在这些情况会 `sys.exit` 中止、不写任何文件：atlas 结构与预期不符、Head/Eye 候选数量不是 2、某个区域匹配不唯一、新矩形越出页边界、仍有区域覆盖率低于 5%。所以可以放心先跑一遍看输出。

脚本会打印新旧 `bounds` 对照表和每个区域的覆盖率，确认无误后文件已写入。

### 适配到其他资源包

复制一份脚本，改顶部这几项：

| 常量 | 说明 |
| --- | --- |
| `ASSET_DIR` | `Assets/Art/Spine/` 下已导入的资源目录 |
| `SOURCE_DIR` | `Recovery/` 下的源目录，写回时同步修改，避免重新导入又变回坏的 |
| `PAGE1` | 需要重建坐标的页文件名 |
| `DECLARED` | 该页每个区域的**原始声明尺寸**，从损坏前的 atlas 里抄 |
| `PAD` | 重打包时每块美术的留白像素，默认 3 |

Head/Mask 与 Eye 的消歧是这个资源特有的，换资源时按实际重名/同尺寸情况调整或删掉。

## 三、修复后验证

1. 让 Unity 重新导入被改的 `.atlas.txt`（切回编辑器或对文件 `Reimport`）；
2. 把 `SkeletonDataAsset` 拖进场景，或用 Spine 的预览窗口看装配是否完整。

若走 Unity Pipeline，可写一段临时 `run_script`：重新导入 atlas → 加载 `SkeletonDataAsset` → `EditorInstantiation.InstantiateSkeletonAnimation` → 相机渲染截图存 PNG，肉眼比对。

## 已知局限

- 半尺寸贴图修好后**分辨率仍是原始的一半**，这是源数据本身的问题，坐标修复无法还原像素。
- 眼睛等叠加件的边缘可能有一圈极淡的接缝，来自 PMA 转直通 alpha 时低 alpha 像素的色彩误差，不是坐标偏移。已验证当前对齐是像素级最优。
- 彻底干净的做法是重新导出源资源；坐标重建是在拿不到源工程时的补救。
